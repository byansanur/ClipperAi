# Backend MVP Summary

This document summarizes the completion of the Minimum Viable Product (MVP) phase for the **ClipperAi Backend**.

## 🎯 Achievements
The ClipperAi backend is now fully operational. It can receive a YouTube URL, intelligently analyze the most engaging moments, and automatically generate short vertical clips (9:16 aspect ratio). The entire process runs completely on your local machine.

## 🛠 Tech Stack & Tools
- **Language**: Go 1.21+
- **Web Framework**: Gin HTTP
- **AI/LLM**: Ollama (Running locally, default model: `llama3.2`)
- **Media Processing**: FFmpeg & yt-dlp
- **Configuration**: `godotenv` (.env file)

## ✨ Key Features Implemented

1. **Asynchronous API (Polling & Cancellation)**
   - `POST /api/v1/clips`: Accepts a video URL, generates a Job ID (UUID), and immediately returns an HTTP 202 Accepted response.
   - `GET /api/v1/clips/:id`: Allows the client to check the job status (`processing`, `completed`, `failed`).
   - `DELETE /api/v1/clips/:id`: Instantly cancels a background processing job, freeing up system resources.

2. **Smart Processing Pipeline**
   - **Transcript Download**: Fetches auto-generated subtitles directly from YouTube.
   - **Heuristic Scoring**: Splits the transcript into 5-minute chunks and scores them based on punctuation (exclamation/question marks) and emotional keywords (e.g., *wow, crazy, shocking*).
   - **LLM Timestamp Extraction**: Sends the highest-scoring chunk to Ollama, intelligently extracting 30-60 seconds of the most engaging moments.
   - **Video Slicing & Cropping**: Downloads the video via yt-dlp, trims it based on the LLM's timestamps, and reformats the aspect ratio to 9:16 using FFmpeg.

## 🐛 Critical Issues Resolved

During the MVP phase, several edge cases and bugs were addressed to ensure the system remains robust:

1. **LLM Timestamp Hallucinations**
   - *Problem*: The LLM would occasionally invent timestamps (e.g., 10 hours) because it lacked a strict time reference.
   - *Solution*: Modified the VTT parser to inject inline timestamps (`[HH:MM:SS]`) directly into the transcript text. The prompt was also updated to strictly limit the LLM to only select times explicitly present in the text.

2. **Apple QuickTime Compatibility**
   - *Problem*: Videos generated by FFmpeg couldn't be played natively on macOS/iOS via QuickTime.
   - *Solution*: Forced FFmpeg to use Apple's standard pixel format (`-pix_fmt yuv420p`) and ensured video dimensions are always even numbers using a specialized crop filter (`crop=floor(ih*9/16/2)*2:floor(ih/2)*2`).

3. **yt-dlp "HTTP 429: Too Many Requests" Errors**
   - *Problem*: YouTube rate-limited the application when attempting to download multi-language subtitles rapidly.
   - *Solution*: Implemented "Partial Failure Tolerance". If the English subtitles fail to download but the Indonesian ones succeed, the system continues processing instead of aborting the job.

4. **Flexible Configuration**
   - Migrated from hardcoded configurations to a `.env`-based system using `godotenv`. Users can now easily adjust the `PORT`, `OLLAMA_MODEL`, and output directory without recompiling the code.

5. **Resource Leak Prevention (Context Cancellation)**
   - *Problem*: If a user canceled the process on the frontend, the backend would continue running FFmpeg, wasting CPU cycles.
   - *Solution*: Injected `context.Context` and its `CancelFunc` into `exec.CommandContext`. Now, when the `DELETE` API is called, yt-dlp and FFmpeg are programmatically terminated (`SIGKILL`) instantly.
